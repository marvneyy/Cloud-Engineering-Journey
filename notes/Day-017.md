# 🧠 1. What is ARP?

**ARP = Address Resolution Protocol**

ARP is used to find the **MAC address associated with a known IP address on a local network**.

### Simple flow

```text
IP Address
    ↓
   ARP
    ↓
MAC Address
```

### Remember

```text
DNS = Domain → IP
ARP = IP → MAC
```

---

# 🔗 2. IP Address vs MAC Address

### Layer 3 — IP Address

Identifies the device using a network address.

```text
192.168.1.20
```

### Layer 2 — MAC Address

Identifies the network interface used for local Ethernet communication.

```text
AA-BB-CC-DD-EE-FF
```

### The problem ARP solves

PC A knows PC B's IP:

```text
PC B IP = 192.168.1.20
```

But PC A does not know PC B's MAC:

```text
PC B MAC = ?
```

ARP finds the MAC address.

---

# 📡 3. ARP Request — Broadcast

Example network:

```text
PC A                         PC B
IP: 192.168.1.10             IP: 192.168.1.20
MAC: AA-AA-AA-AA-AA-AA       MAC: BB-BB-BB-BB-BB-BB
       │                            │
       └──────── Switch ────────────┘
```

PC A wants to communicate with PC B.

PC A knows:

```text
192.168.1.20
```

But it does not know the MAC address.

So PC A sends an **ARP Request**:

```text
"Who has 192.168.1.20?"
```

Because PC A does not know which device owns that IP, the request is sent as a **broadcast** on the local network.

The switch forwards the broadcast to the devices on that local network.

---

# 📩 4. ARP Reply

PC B receives the ARP Request and recognizes that:

```text
192.168.1.20
```

is its own IP address.

PC B responds with an **ARP Reply**:

```text
"192.168.1.20 is me.
My MAC address is BB-BB-BB-BB-BB-BB."
```

PC A now knows:

```text
192.168.1.20
        ↓
BB-BB-BB-BB-BB-BB
```

This is the **IP → MAC mapping** provided by ARP.

---

# 🔄 5. Complete ARP Communication Flow

```text
PC A
 │
 │ Destination IP = 192.168.1.20
 │ MAC address unknown
 ↓
ARP Request
"Who has 192.168.1.20?"
 │
 │ Broadcast
 ↓
Switch
 │
 ├──→ PC B
 │
 └──→ Other local devices
       │
       └── Ignore if IP is not theirs

PC B
 │
 │ ARP Reply
 ↓
"192.168.1.20 → BB-BB-BB-BB-BB-BB"
 │
 ↓
PC A
 │
 │ Stores IP → MAC mapping
 ↓
Ethernet Frame
 │
 ↓
Switch
 │
 ↓
PC B
```

### Key point

> **ARP finds the destination MAC address; the switch uses the MAC address for local Layer 2 delivery.**

---

# 💾 6. ARP Cache / ARP Table

The computer stores learned IP-to-MAC mappings in an ARP table.

Example:

```text
IP Address       MAC Address
-----------------------------------
192.168.1.20     BB-BB-BB-BB-BB-BB
192.168.1.30     11-22-33-44-55-66
```

This allows the computer to check the existing mapping before needing to discover it again.

# 💻 7. ARP Commands — Windows

## View the ARP Table

```powershell
arp -a
```

**Purpose:**  
Displays the ARP table stored on the computer.

Important columns:

```text
Internet Address = IP Address
Physical Address = MAC Address
Type             = Entry type
```

Example:

```text
192.168.1.87    66-be-76-b3-bc-28    dynamic
```

This means:

```text
192.168.1.87 → 66-BE-76-B3-BC-28
```

---

## Clear the ARP Cache

```powershell
arp -d
```

**Purpose:**  
Clears ARP entries so the computer can learn the mappings again.

> **Note:** On Windows, administrator privileges may be required.

---

## Test Connectivity

```powershell
ping 192.168.1.87
```

**Purpose:**  
Tests connectivity to the specified IP address using ICMP.

> A failed ping does not automatically mean that ARP failed.

# 🔬 9. ARP Cache Experiment

### Step 1 — View the ARP table

```powershell
arp -a
```

The iPhone mapping was present:

```text
192.168.1.87 → 66-BE-76-B3-BC-28
```

### Step 2 — Clear the ARP cache

```powershell
arp -d
```

The iPhone's dynamic ARP entry disappeared.

### Step 3 — Attempt communication

```powershell
ping 192.168.1.87
```

The iPhone did not respond to the ping:

```text
Request timed out.
```

### Step 4 — Check the ARP table again

```powershell
arp -a
```

The mapping appeared again:

```text
192.168.1.87    66-be-76-b3-bc-28    dynamic
```

### Observation

The ARP entry was cleared and then learned again after communication was attempted.

This demonstrated the **IP → MAC mapping process** on my local network.
