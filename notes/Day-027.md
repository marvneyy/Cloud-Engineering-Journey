### 1. NAT Gateway

A **NAT Gateway** allows resources in a private subnet to initiate connections to the internet without needing their own public IP address.

#### 🏠 Simple Example

Imagine you're inside your house and want to go outside.

- **You:** Private EC2 server
- **Way out:** NAT Gateway
- **Outside world:** Internet

You can go outside and return, but strangers cannot use that same connection to start a new visit directly to your room.

#### ☁️ How It Works in AWS

Imagine a private EC2 server needs to download software updates.

```text
Private EC2 Server
        ↓
Private Route Table
0.0.0.0/0 → NAT Gateway
        ↓
NAT Gateway
        ↓
Internet Gateway
        ↓
Internet
```

1. The EC2 server requests a software update.
2. The route table directs internet-bound traffic to the NAT Gateway.
3. The NAT Gateway forwards the traffic toward the internet through the Internet Gateway.
4. The response returns through the NAT Gateway to the server.

**Remember:**
- Route Table = Chooses the network path.
- NAT Gateway = Handles network address translation for outbound internet access.
- A public NAT Gateway is placed in a public subnet.
- Security rules and network configuration still matter.

### 2. Elastic IP

An **Elastic IP** is a static public IPv4 address allocated in AWS that can be associated with a supported AWS resource.

#### 🏠 Simple Example

Imagine your house has a permanent address: House No. 25.

- House = AWS resource
- Address = IP address
- Permanent public address = Elastic IP

#### ☁️ How It Works with a NAT Gateway

A public NAT Gateway commonly uses an Elastic IP to communicate with the internet.

```text
Private EC2 Server
        ↓
Private Route Table
        ↓
NAT Gateway
(Uses an Elastic IP)
        ↓
Internet Gateway
        ↓
Internet
```

**Remember:**
- Elastic IP = Static public IPv4 address.
- NAT Gateway = Handles outbound network address translation.
- Route Table = Decides where traffic goes.

🧠 **Memory trick:** Elastic IP is like a permanent public address.

### 3. Private Subnet Routing

**Private Subnet Routing** means deciding which path traffic from a private subnet should take to reach its destination.

#### 🏠 Simple Example

Imagine you're inside your house and want to go to a supermarket.

- You = EC2 server
- House = Private subnet
- Road signs = Route table
- Road toward the internet = Network path through the NAT Gateway

The route table chooses the path that network traffic should follow.

#### What Does `0.0.0.0/0 → NAT Gateway` Mean?

Read it like this:

“Send traffic to destinations without a more-specific matching route to the NAT Gateway.”

- `0.0.0.0/0` = Default route for IPv4 destinations.
- NAT Gateway = Target for that route.

#### ☁️ Traffic Flow

```text
Private EC2 Server
        ↓
Private Route Table
0.0.0.0/0 → NAT Gateway
        ↓
NAT Gateway
        ↓
Internet Gateway
        ↓
Internet
```

This setup allows a private server to initiate internet connections without needing its own public IP address.

### 5. ⚠️ AWS Cost Warning

**NAT Gateways can incur charges while provisioned**, including hourly charges and data-processing charges.

To avoid these charges, I did not:
- Create a NAT Gateway.
- Allocate an Elastic IP for this lab.
- Launch an EC2 instance.
- Change my private route table.
