# 📅 Day 25 — Security Groups vs NACLs

## 🎯 Goal

Understand firewalls, Security Groups, NACLs, and the difference between stateful and stateless firewalls in AWS.

---

## 📚 Topics Covered

- What is a Firewall?
- What is a Security Group?
- What is a Network Access Control List (NACL)?
- What is a Connection?
- Stateful vs Stateless Firewalls
- Security Group vs NACL

---

# 1. What Is a Firewall?

A **firewall** is a security system that controls which network traffic is allowed and which traffic is blocked.

### 🏠 Real-Life Example

Imagine a building with a security guard at the entrance.

- If a person has permission, the guard allows them to enter.
- If a person does not have permission, the guard blocks them.

A firewall works in a similar way. It checks network traffic and allows or blocks it according to its rules.

**Remember:** A firewall controls network traffic.

---

# 2. What Is a Security Group (SG)?

A **Security Group** is a virtual firewall for AWS resources, such as EC2 instances.

It controls which traffic is allowed to enter and leave a resource.

### Two Types of Traffic

| Type | Simple Meaning | Example |
|---|---|---|
| Inbound | Traffic coming into a resource | Connecting to an EC2 server |
| Outbound | Traffic leaving a resource | An EC2 server sending a request to a website |

### 🏠 Real-Life Example

Imagine a security guard protecting a particular room in a building.

The guard checks which people are allowed to enter or leave that room.

Similarly, a Security Group controls allowed network traffic for an AWS resource.

### Example: SSH Access

Suppose you want to connect to your EC2 server using SSH.

You can configure a Security Group to allow SSH traffic on **port 22** only from your home IP address.

**Remember:**
- Security Group = Resource-level virtual firewall.
- Security Group is **stateful**.
- Security Groups use allow rules; they do not have deny rules.

---

# 3. What Is a Network Access Control List (NACL)?

**NACL = Network Access Control List.**

A NACL is a firewall that controls network traffic entering and leaving an AWS subnet.

Unlike a Security Group, a NACL works at the **subnet level**.

### 🏠 Real-Life Example

Imagine an apartment complex with a security checkpoint at its main entrance.

The checkpoint controls which people can enter or leave the complex.

Similarly, a NACL controls network traffic entering or leaving a subnet.

### Where Does a NACL Work?

```text
                 AWS VPC
                    |
                    v
          NACL — Subnet-level firewall
                    |
                    v
                  Subnet
                    |
                    v
             EC2 Instances
```

A NACL protects traffic at the subnet boundary. It is not an individual firewall attached directly to one EC2 instance.

### How Does a NACL Allow or Deny Traffic?

A NACL has numbered rules.

| Rule Number | Action | Meaning |
|---|---|---|
| 100 | Allow | Permit matching traffic |
| 110 | Deny | Block matching traffic |

AWS evaluates rules in ascending numerical order. The **first matching rule** determines whether the traffic is allowed or denied.

For example, if traffic matches rule 100 and that rule says `ALLOW`, the NACL allows that traffic.

**Remember:**
- NACL = Subnet-level firewall.
- NACL is **stateless**.
- NACL supports both allow and deny rules.

---

# 4. What Is a Connection?

A connection is a communication session between two devices or systems.

### Example

Your computer wants to access a server.

```text
YOUR COMPUTER
      |
      |  Request
      v
    SERVER
      |
      |  Reply
      v
YOUR COMPUTER
```

Your computer sends a request, and the server sends a reply.

A firewall must decide whether the traffic is allowed.

This helps us understand the difference between stateful and stateless firewalls.

---

# 5. What Is a Stateful Firewall?

**Stateful = The firewall tracks connections.**

A stateful firewall keeps track of established connections.

When traffic is allowed and a connection is established, the firewall automatically allows the response traffic associated with that connection.

A separate reverse-direction rule is not required just to allow that response.

### Example: Security Group

1. Your computer sends a request to an EC2 server.
2. The Security Group allows the connection.
3. The server sends a reply through that established connection.
4. The Security Group automatically allows the response traffic.

### 🏠 Real-Life Example

Imagine a security guard who remembers that you were already allowed into a building.

When you return through the expected process, the guard recognises the existing permission instead of treating the response as a completely new connection.

**Remember:** Stateful firewalls track connections.

**AWS Example:** Security Group.

---

# 6. What Is a Stateless Firewall?

**Stateless = The firewall does not track connections for automatic return-traffic handling.**

A stateless firewall checks traffic against its rules without automatically allowing response traffic just because the original request was allowed.

### Example: NACL

1. Your computer sends a request to a server.
2. The NACL allows the outgoing or incoming traffic according to its rules.
3. The server sends a reply.
4. The NACL must have an appropriate rule allowing the return traffic.

### 🏠 Real-Life Example

Imagine a security guard who checks the rules every time someone passes through a checkpoint.

Even if the guard allowed the person to pass earlier, the return journey must also satisfy the applicable rules.

**Remember:** Stateless firewalls require rules for return traffic.

**AWS Example:** Network Access Control List (NACL).

---

# 7. Security Group vs NACL

This is the most important comparison in Day 25.

| Feature | Security Group (SG) | Network ACL (NACL) |
|---|---|---|
| Main purpose | Controls traffic for a resource | Controls traffic at a subnet boundary |
| Level | Resource level | Subnet level |
| Type | Stateful | Stateless |
| Rules | Allow rules | Allow and deny rules |
| Return traffic | Automatically allowed for tracked connections | Must be permitted by separate matching rules |
| Rule evaluation | All applicable rules are evaluated together | Numbered rules are evaluated in ascending order; first match applies |

### Easy Memory Trick 🧠

**SG = Stateful + Resource level**

**NACL = Stateless + Subnet level**

---

# 8. Quick Revision

### What is a Firewall?

A system that allows or blocks network traffic according to rules.

### What is a Security Group?

A stateful virtual firewall that controls allowed traffic for resources such as EC2 instances.

### What is a NACL?

A stateless firewall that controls traffic entering and leaving a subnet.

### What Does Stateful Mean?

The firewall tracks connections and automatically allows the response traffic associated with an established connection.

### What Does Stateless Mean?

The firewall does not automatically allow return traffic based on the original request. Matching rules must permit the return traffic.

---

# 9. Final Summary

```text
FIREWALL
   |
   └── Controls allowed and blocked traffic

SECURITY GROUP
   |
   ├── Resource level
   ├── Stateful
   └── Allow rules

NACL
   |
   ├── Subnet level
   ├── Stateless
   └── Allow and deny rules
```

**The three most important things to remember:**

1. A Security Group is stateful and works at the resource level.
2. A NACL is stateless and works at the subnet level.
3. A Security Group automatically allows response traffic for tracked connections, while a NACL needs appropriate rules for return traffic.
