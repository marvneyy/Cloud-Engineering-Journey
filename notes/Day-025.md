## 📅 Day 25 — Security Groups vs. NACLs

**Goal:** Security Groups vs NACLs

---

#### 1. What is a Firewall?

A firewall is a security system that controls which network traffic is allowed or blocked.

Example: A security guard checks who can enter a building. A firewall checks network traffic.

---

### 2. What is a Security Group?

A Security Group is a virtual firewall for AWS resources such as EC2 instances.
It controls:
- Inbound traffic: Traffic coming into a resource.
- Outbound traffic: Traffic leaving a resource.

Example: You can configure a Security Group to allow SSH access to a server only from your home IP address.

---

### 3. Network Access Control List (NACL) ?

NACL = Network Access Control List.

A NACL is a firewall that controls network traffic entering and leaving an AWS subnet.

Imagine a college with a security checkpoint at its main entrance.

The guard checks who can enter and who must be denied.

Similarly, a NACL checks network traffic and decides whether to allow or deny it.

#### . Where does a NACL work?

AWS VPC

NACL — Subnet-level firewall

Checks traffic entering or leaving the subnet

Subnet

EC2 instances can be inside this subnet

Remember: A NACL works at the subnet level, not as an individual firewall attached to one EC2 instance.

#### . How does a NACL allow or deny traffic?

Imagine these rules:

| Rule | Action | Meaning                 |
| ---- | ------ | ----------------------- |
| 100  | Allow  | Permit matching traffic |
| 110  | Deny   | Block matching traffic  |

NACL rules have numbers, and AWS evaluates them in ascending order. The first matching rule determines the result.

For example, if traffic matches rule 100, which says Allow, it is allowed by the NACL.

#### . What does stateless mean?

This is the most important part!

Imagine your computer sends a request to a server.

- The outgoing request is allowed.
- The server sends a reply back.
- The NACL must also have a rule allowing that return traffic.

Stateless means the NACL does not automatically allow return traffic just because it allowed the original request.

---

### 4. Stateful vs Stateless firewalls

#### 1. First, what is a connection?

Imagine your computer sends a request to a server, and the server sends a reply.

             Your Computer

              -> Request

                 Server

               <- Reply

       Your Computer receives the reply

The firewall must decide whether this traffic is allowed.

#### 2. What is Stateful?

Stateful = The firewall remembers the connection.

For example, a Security Group allows your computer to connect to a server.

When the server sends a reply through that established connection, the Security Group automatically allows the response traffic. You do not need a separate reverse-direction rule just for that response.

Think of a security guard who remembers that you were already allowed inside.

#### 3. What is Stateless?

Stateless = The firewall does not automatically remember the connection for allowing return traffic.

For example, a NACL allows your computer's request to reach a server.

When the server sends a reply, the NACL still needs an appropriate rule allowing that return traffic.

Think of a security guard who checks permission every time, even when someone is returning.

#### 4. The main difference

| Stateful                                                          | Stateless                                                        |
| ----------------------------------------------------------------- | ---------------------------------------------------------------- |
| Tracks connections                                                | Does not track connections for automatic return-traffic handling |
| Response traffic is automatically allowed for tracked connections | Return traffic needs its own matching rule                       |
| AWS example: Security Group                                       | AWS example: NACL                                                |

Remember: Stateful remembers the connection. Stateless does not automatically allow the response.
