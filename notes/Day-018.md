# 1. 🌐 What is HTTP?

**HTTP (Hypertext Transfer Protocol)** is a protocol used for communication between a client and a web server.

Basic communication flow:

```text
Client
   ↓
HTTP Request
   ↓
Web Server
   ↓
HTTP Response
   ↓
Client
```

For example, when opening a website:

```text
Browser
   ↓
"Give me this webpage"
   ↓
Web Server
   ↓
"Here is the response"
   ↓
Browser
```

---

# 2. 📤 What is an HTTP Request?

An **HTTP request** is a message sent by the client (such as a web browser) to a web server asking for a resource or requesting an action.

Example:

```text
Browser
   │
   │ HTTP Request
   ▼
Web Server
```

---

# 3. 🔄 HTTP Request Methods

## GET

**GET** is used to request or retrieve data from a server.

Example:

```text
Browser
   ↓
GET /index.html
   ↓
Server
   ↓
Response
```

Examples:

- Request a webpage
- Request an image
- Retrieve information
- Retrieve a list of products

### 🧠 Remember

```text
GET → "Give me"
```

---

## POST

**POST** is used to send data to a server for processing or storage.

For example, when submitting a signup form:

```text
Browser
   ↓
POST
   ↓
Name + Email + Password
   ↓
Server
   ↓
Processes the data
```

### 🧠 Remember

```text
POST → "Here is data"
```

---

## GET vs POST

| GET | POST |
|---|---|
| Requests/retrieves data | Sends data to the server |
| Used to retrieve resources | Used to submit data |
| Example: requesting a webpage | Example: submitting a signup form |

### Quick Memory

```text
GET  → "Give me"
POST → "Here is data"
```

---

# 4. 📥 HTTP Response

After receiving an HTTP request, the server sends an **HTTP response** back to the client.

```text
Browser
   │
   │ HTTP Request
   ▼
Server
   │
   │ HTTP Response
   ▼
Browser
```

An HTTP response can contain:

- Status code
- Response headers
- Requested content/data

---

# 5. 📊 HTTP Status Codes

An HTTP status code tells the client what happened to the request.

## 200 — OK

```text
200 OK
```

The request was successful.

```text
Browser
   ↓
GET /index.html
   ↓
Server
   ↓
200 OK
   ↓
Webpage
```

### 🧠 Remember

```text
200 → Success
```

---

## 404 — Not Found

```text
404 Not Found
```

The requested resource could not be found.

Example:

```text
example.com/abcxyz
```

If the requested page does not exist, the server may return:

```text
404 Not Found
```

### 🧠 Remember

```text
404 → Not Found
```

---

## 500 — Internal Server Error

```text
500 Internal Server Error
```

The server encountered an unexpected problem while processing the request.

```text
Browser
   ↓
Request
   ↓
Server
   ↓
❌ Server-side problem
   ↓
500 Internal Server Error
```

### 🧠 Remember

```text
500 → Server problem
```

---

# 6. 🔴 4xx vs 5xx

An important distinction when troubleshooting HTTP errors is the difference between **4xx** and **5xx** status codes.

### 4xx — Client/Request Errors

Generally indicate that there is a problem with the request or the requested resource.

Example:

```text
404 Not Found
```

### 5xx — Server Errors

Indicate that the server encountered a problem while handling the request.

Example:

```text
500 Internal Server Error
```

### 🧠 Quick Memory

```text
4xx → Client/request side
5xx → Server side
```

---

# 7. 🔐 HTTP vs HTTPS

## HTTP

HTTP is used for web communication without TLS protection.

```text
HTTP
↓
Web communication
```

## HTTPS

HTTPS is HTTP secured using TLS.

```text
HTTP
   +
TLS
   ↓
HTTPS
```

When a website uses:

```text
https://
```

the communication uses TLS protection.

---

# 8. 🔒 SSL and TLS

## SSL

**SSL (Secure Sockets Layer)** is an older security protocol that was designed to protect communication over a network.

```text
SSL
↓
Older security protocol
```

---

## TLS

**TLS (Transport Layer Security)** is the newer security protocol that replaced SSL.

```text
TLS
↓
Newer security protocol
```

### 🧠 Remember

```text
SSL → Older protocol
TLS → Newer protocol
```

Modern HTTPS connections use **TLS**, although the term "SSL certificate" is still commonly used.

---

# 9. 🛡️ What Does TLS Provide?

At this learning level, the three important concepts are:

### 🔐 Encryption

Protects communication so the data is not simply readable while travelling across the network.

### 🪪 Authentication

Digital certificates help the browser verify the identity of the website.

### 🛡️ Integrity

Helps detect whether protected data has been modified during transmission.

```text
TLS
├── 🔐 Encryption
├── 🪪 Authentication
└── 🛡️ Integrity
```

---

# 10. 🔑 HTTPS

The most important relationship to remember:

```text
HTTP
  +
TLS
  ↓
HTTPS
```

**HTTPS = HTTP secured with TLS.**

### HTTP

```text
http://example.com
```

### HTTPS

```text
https://example.com
```

HTTPS provides TLS-protected communication between the browser and the web server.

# 11. 🧪 Hands-On Lab — Browser Developer Tools

## Objective

Inspect HTTP/HTTPS requests using the browser's **Developer Tools → Network** tab.

## Tool Used

- Google Chrome Developer Tools

## Steps Performed

1. Opened Google Chrome.
2. Opened Developer Tools using `F12`.
3. Navigated to the **Network** tab.
4. Opened Google.
5. Selected a network request.
6. Inspected the request details and response headers.

## 🔎 Observations

### Request URL

The selected request used HTTPS:

```text
https://www.gstatic.com/...
```

This shows that the request was made using HTTPS.

### Request Method

```text
GET
```

The browser used a GET request to retrieve the resource.

### Status Code

```text
200 OK (from disk cache)
```

The request was successful.

The **"from disk cache"** message indicates that Chrome served the resource from its local cache.

### Response Headers

Inspected response headers including:

```text
Access-Control-Allow-Origin
Age
Alt-Svc
```
