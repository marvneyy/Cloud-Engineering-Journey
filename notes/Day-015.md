# 1️⃣ OSI — Open Systems Interconnection

## What is OSI?

**OSI = Open Systems Interconnection**

OSI is a model that divides/organizes computer network communication into **7 layers** to help us understand how data is sent from one computer to another.

### 🗣️ Simple Manglish

> OSI enn parayunnath oru computer-il ninnu vere oru computer-lekku message/data send cheyyunna network communication-ne **7 layers aayi divide cheytha model** aanu.

---

## 🔢 The 7 OSI Layers

```text
7 — Application
6 — Presentation
5 — Session
4 — Transport
3 — Network
2 — Data Link
1 — Physical
````

### 📤 Sending

```text
Application
     ↓
Presentation
     ↓
Session
     ↓
Transport
     ↓
Network
     ↓
Data Link
     ↓
Physical
```

**Sending → Layer 7 to Layer 1**

### 📥 Receiving

```text
Physical
     ↓
Data Link
     ↓
Network
     ↓
Transport
     ↓
Session
     ↓
Presentation
     ↓
Application
```

**Receiving → Layer 1 to Layer 7**

---

## 🧠 Simple Understanding

Think of the OSI model as **7 different jobs** involved in network communication.

```text
7️⃣ Application   → User/Application side
6️⃣ Presentation  → Data format
5️⃣ Session       → Communication session
4️⃣ Transport     → Data transport
3️⃣ Network       → Finding the network/device path
2️⃣ Data Link     → Local network communication
1️⃣ Physical      → Actual signals/cables
```

### 🧠 Easy Memory

**7 → 1**

> Application → Presentation → Session → Transport → Network → Data Link → Physical

# 2️⃣ OSI Layer 4 — Transport Layer

**Layer 4 = Transport Layer**

The Transport Layer helps transport data between applications/processes over a network.

### 🗣️ Simple Manglish

> Transport Layer = data oru computer-il ninnum vere computer-lekku pokumbol, athu correct application/process-ilekku transport cheyyan help cheyyunna layer.

### Main Protocols

```text
Layer 4 — Transport Layer
        ↓
    ┌───┴───┐
   TCP     UDP
```

* TCP
* UDP

---

## ❓ Why do we need the Transport Layer?

A computer can have multiple applications using the network at the same time.

For example:

* Chrome 🌐
* WhatsApp 💬
* YouTube ▶️

Network vazhi data varumbol, aa data ethu application/process-umaayi sambandhappettathaanennu handle cheyyan Transport Layer important aanu.

### 🧠 Simple Memory

> **Transport Layer = Data correct application/process-ilekku transport cheyyan help cheyyunna layer.**

# 3️⃣ TCP vs UDP

## What is a Protocol?

> **Protocol = Communication rules**

Simple aayi:

> Two people communicate cheyyumbol rules follow cheyyunnath pole, computers-um data communicate cheyyumbol protocols use cheyyunnu.

---

## TCP

**TCP = Transmission Control Protocol**

TCP is a Transport Layer protocol.

TCP data **reliable aayi deliver cheyyan** vendi use cheyyunnu.

### 📦 Simple Example

Nee oru important file friend-inu send cheyyunnu.

TCP use cheythal, data properly reach cheyyunnathum correct order-il ethunnathum important aanu.

```text
Sender
   ↓
  TCP
   ↓
Network
   ↓
  TCP
   ↓
Receiver
```

### 🧠 TCP Main Idea

> **TCP = Reliability**

TCP is **connection-oriented**.

### What does connection-oriented mean?

Data exchange start cheyyunnathinu munpu, senderum receiverum thammil oru connection establish cheyyunnu.

### TCP Memory

> **TCP = Reliable + Connection-Oriented**

### TCP Use Cases

* Web pages
* Email
* File transfer

---

# UDP

**UDP = User Datagram Protocol**

UDP is also a Transport Layer protocol.

UDP is useful when **speed/simple communication** is important.

### 🎥 Simple Example

Imagine nee live video kaanunnu.

Oro small piece of data late aayi vannal, athu wait cheythu resend cheyyunnathinu pakaram **speed maintain cheyyunnath** important aakum.

UDP ivide useful aanu.

### 🧠 UDP Main Idea

> **UDP = Speed / Simple Communication**

UDP is **connectionless**.

Athayathu TCP pole connection establish cheyyenda mechanism illa.

### UDP Memory

> **UDP = Fast / Simple**

### UDP Use Cases

* Voice
* Video
* Gaming
* DNS

---

# 🔄 TCP vs UDP

| TCP                          | UDP                            |
| ---------------------------- | ------------------------------ |
| Reliable                     | Fast / Simple                  |
| Connection-oriented          | Connectionless                 |
| Connection establish cheyyum | Connection establish cheyyenda |
| Reliability important        | Speed important                |
| Web pages                    | Voice                          |
| Email                        | Video                          |
| File transfer                | Gaming                         |
|                              | DNS                            |

### 🧠 Easy Memory

```text
TCP → Reliability 📦
UDP → Speed / Simple ⚡
```

# 4️⃣ TCP Three-Way Handshake

TCP connection start cheyyumbol client/server thammil connection establish cheyyan oru process und.

Athaan **TCP Three-Way Handshake**.

The three steps are:

```text
SYN → SYN-ACK → ACK
```

---

## 1️⃣ SYN

**SYN = Synchronize**

Simple aayi:

> Client server-inodu parayunnu: **"Hi, enikku oru TCP connection start cheyyanam."**

```text
Client 💻
   |
   | SYN →
   |
Server 🖥️
```

### 🧠 Memory

> **SYN = Connection start cheyyanulla first request.**

---

## 2️⃣ SYN-ACK

Server-inu client-inde SYN kitti.

Server reply cheyyunnu:

```text
Client 💻
   |
   | SYN →
   |
Server 🖥️
   |
   | ← SYN-ACK
   |
```

### Simple Meaning

> Server parayunnu: **"Okay, request kitti. Njanum connection establish cheyyan ready aanu."**

### 🧠 Memory

> **SYN = "Can we connect?"**
> **SYN-ACK = "Yes, I received you and I'm ready."**

---

## 3️⃣ ACK

Ippo client SYN-ACK receive cheythu.

Client final reply ayakkum:

```text
Client 💻
   |
   | SYN →
   |
Server 🖥️
   |
   | ← SYN-ACK
   |
   | ACK →
   |
```

**ACK = Acknowledgment**

Simple aayi:

> Client parayunnu: **"Okay, server. Ninte reply enikku kitti."**

Ithode TCP Three-Way Handshake complete aakum.

### 🧠 Full Memory

```text
SYN
→ Can we connect?

SYN-ACK
→ Yes, I received you.

ACK
→ Okay, I received your reply.
```

---

## 🔄 TCP Three-Way Handshake — Full Flow

```text
1️⃣ SYN
Client → Server
Requests a connection.

2️⃣ SYN-ACK
Server → Client
Acknowledges the request and responds.

3️⃣ ACK
Client → Server
Acknowledges the server's response.

Result:
TCP connection is established.
```

### 🧠 Easy Memory

> **SYN → SYN-ACK → ACK**

# 5️⃣ Flow Control

## What is Flow Control?

> **Sender fast aayi data ayakkumbol receiver overload aakathirikkan TCP data flow control cheyyunnathaanu Flow Control.**

### English

> Flow Control helps TCP control the amount/rate of data sent so that the receiver is not overwhelmed.

### 🧠 Simple Idea

```text
Fast Sender
     ↓
     ↓  Too much data
     ↓
Slow Receiver
     ↓
Flow Control
     ↓
Avoid Receiver Overload
```

### 🥤 Simple Example

Oru sender valare fast aayi data ayakkunnu.

But receiver-kku athrayum fast aayi data handle cheyyan pattunnilla.

Appol receiver overload aakathirikkan **data flow control cheyyunnu**.

### 🧠 One-Line Memory

> **Flow Control = Receiver overload aakathirikkan data flow control cheyyuka.**
