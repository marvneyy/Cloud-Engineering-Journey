# 1. What is DNS?

**DNS = Domain Name System**

DNS helps resolve a domain name to its corresponding IP address.

### Basic Flow

```text
Domain Name
     ↓
    DNS
     ↓
 IP Address
     ↓
 Web Server
````

### Example

```text
amazon.ae
     ↓
    DNS
     ↓
 IP Address
     ↓
 Web Server
```

### Why do we need DNS?

Humans can easily remember domain names:

```text
google.com
amazon.ae
youtube.com
```

But computers communicate using IP addresses.

Without DNS, users would need to remember IP addresses instead of easy-to-remember domain names.

### 🧠 Memory

```text
Human   → Domain Name
Network → IP Address
DNS     → Connects the name with DNS information/IP
```

**Simple analogy:**

> DNS = Internet Phonebook

---

# 2. Root Servers

Root servers are at the **top of the DNS hierarchy**.

They normally do **not** provide the final IP address.

Instead, they direct the DNS query toward the appropriate **TLD nameserver**.

### Example

```text
example.com
     ↓
Root Server
     ↓
.com TLD Nameserver
```

### Common TLDs

```text
.com
.in
.ae
.org
```

### What does the Root Server do?

The root server looks at the domain's TLD and helps direct the query to the appropriate TLD nameserver.

Example:

```text
amazon.ae
     ↓
Root Server
     ↓
.ae TLD Nameserver
```

### 🧠 Memory

> **Root → Which TLD?**

---

# 3. TLD — Top-Level Domain

**TLD = Top-Level Domain**

The TLD is the last part of a domain name.

### Examples

| Domain          | TLD    |
| --------------- | ------ |
| `google.com`    | `.com` |
| `amazon.ae`     | `.ae`  |
| `example.in`    | `.in`  |
| `wikipedia.org` | `.org` |

### Role of the TLD

After the Root Server directs the query to the correct TLD nameserver, the TLD nameserver helps identify where the domain's **authoritative nameserver** can be found.

### Example

```text
amazon.ae
     ↓
Root Server
     ↓
.ae TLD Nameserver
     ↓
Authoritative Nameserver
```

### 🧠 Memory

> **TLD → Which Authoritative Nameserver?**

### Important Distinction

```text
.ae
```

is the **TLD**.

The **.ae TLD nameservers** are the DNS infrastructure that handles information about domains under `.ae`.

---

# 4. Authoritative Nameserver

The **Authoritative Nameserver** is the stage that provides the authoritative DNS records for a domain.

### DNS Resolution Chain

```text
Domain
   ↓
Root Server
   ↓
TLD Nameserver
   ↓
Authoritative Nameserver
   ↓
DNS Record
```

### Example

```text
amazon.ae
     ↓
Root Server
     ↓
.ae TLD Nameserver
     ↓
Authoritative Nameserver
     ↓
DNS Record / IP Information
```

The authoritative nameserver contains the authoritative DNS records for the domain.

### 🧠 Memory

```text
Root          → Find TLD
TLD           → Find Authoritative Nameserver
Authoritative → Provide DNS Record
```

# 6. DNS Record Types

The four core record types covered today are:

* A
* CNAME
* MX
* TXT

---

## 6.1 A Record

**A = Address Record**

An A record maps a hostname/domain to an **IPv4 address**.

### Example

```text
www.example.com
       ↓
    A Record
       ↓
192.168.1.10
```

### Another Example

```text
www.example.com → 192.168.1.10
```

### 🧠 Memory

> **A Record = Name → IPv4 Address**

---

## 6.2 CNAME Record

**CNAME = Canonical Name**

A CNAME record points one hostname to another hostname.

### Example

```text
shop.example.com
       ↓
    CNAME
       ↓
www.example.com
```

Unlike an A record, a CNAME does not directly map the hostname to an IP address.

### Example Flow

```text
shop.example.com
       ↓
     CNAME
       ↓
www.example.com
       ↓
    A Record
       ↓
192.168.1.10
```

The DNS lookup can follow the CNAME to obtain the DNS information for the target hostname.

### Why is CNAME useful?

It allows multiple hostnames to point to the same hostname without maintaining a separate IP mapping for each one.

### 🧠 Memory

> **CNAME = Name → Another Name**

---

## 6.3 MX Record

**MX = Mail Exchange**

An MX record specifies which mail server handles email for a domain.

### Example

```text
company.com
     ↓
   MX Record
     ↓
mail.company.com
     ↓
Mail Server
```

### Example Email

```text
To: rahul@company.com
```

The sending mail system needs to know:

> Which mail server handles email for `company.com`?

It checks the domain's **MX record**.

### Conceptual Flow

```text
company.com
     ↓
   MX Record
     ↓
mail.company.com
     ↓
A Record
     ↓
IP Address
     ↓
Mail Server
```

### 🧠 Memory

> **MX = Domain → Mail Server**

---

## 6.4 TXT Record

**TXT = Text Record**

A TXT record stores text information associated with a domain.

### Common Uses

* Domain verification
* Email/security-related information

### Example

```text
company.com
     ↓
  TXT Record
     ↓
Verification Information
```

### 🧠 Memory

> **TXT = Domain → Text Information**

---

# 7. A vs CNAME vs MX vs TXT

| Record    | Main Purpose                  | Maps / Provides           |
| --------- | ----------------------------- | ------------------------- |
| **A**     | IPv4 address mapping          | Name → IPv4               |
| **CNAME** | Hostname alias                | Name → Another Name       |
| **MX**    | Email delivery                | Domain → Mail Server      |
| **TXT**   | Text/verification information | Domain → Text Information |

## 🧪 Day 16 — DNS Hands-On Lab

### Tool Used
`nslookup`

### Command
```powershell
nslookup amazon.ae 8.8.8.8
````

### Purpose

To query DNS and find the IPv4 addresses associated with
the domain `amazon.ae`.

### DNS Server Used

* Server: `dns.google`
* Address: `8.8.8.8`

### Result

```text
Name:    amazon.ae
Addresses:
3.253.176.68
3.253.180.212
3.253.179.62
```

### Observation

The DNS lookup successfully resolved `amazon.ae`
and returned multiple IPv4 addresses.

This demonstrates the basic concept:

`Hostname → IPv4 Address`

This is associated with an **A record**.
