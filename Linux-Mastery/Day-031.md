# 📅 Day 31 — Linux Log Analysis

## 🎯 Goal
Learn how to read system log files, search for specific text, and count matching log lines using Linux commands.

## 📚 What I Learned

### 1. Authentication Log
File: `/var/log/auth.log`

This log contains authentication-related events, including password checks and login activity.

### 2. Commands Used

| Command | Purpose |
|---|---|
| `pwd` | Displays the current working directory |
| `cat` | Displays the contents of a file in the terminal |
| `sudo cat /var/log/auth.log`|	Reads the authentication log with elevated permissions |

## 🔍 Practical Lab

### Search for Failed Events

```bash
sudo cat /var/log/auth.log | grep -i "failed"
```

**Purpose:** Displays log lines containing the word `failed`.

### Count Matching Lines

```bash
sudo grep -i "failed" /var/log/auth.log | wc -l
```

**My result:** 26 matching lines at the time of testing.

**Note:** This is a count of matching log lines, not necessarily the number of unique incidents or attacks.

### Search for Password Failures

```bash
sudo grep -i "password check failed" /var/log/auth.log
```

**Purpose:** Searches for password-check failure messages.

### Count Authentication Failures

```bash
sudo cat /var/log/auth.log | grep -i "authentication" | wc -l
```

**Purpose:** Counts log lines containing `authentication`.

## 🧠 Important Concepts

- **Log file:** Records events generated by a system or application.
- **`grep`:** Searches text for a specified pattern.
- **Pipe (`|`):** Sends one command's output to another command.
- **`wc -l`:** Counts lines in the input.
- **`-i`:** Makes the text search case-insensitive.
- **`sudo`:** Runs a command with elevated privileges when authorized.

## 📝 Key Takeaway

Linux log analysis helps engineers investigate system events and troubleshoot authentication problems. A failed authentication message alone does not prove that a system was hacked.
