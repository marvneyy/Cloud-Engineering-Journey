### 1. What Is an Internet Gateway (IGW)?

**IGW = Internet Gateway**

An Internet Gateway is an AWS component that connects a VPC to the internet when the required network configuration is in place.

### 🧠 Simple Definition

> **Internet Gateway = A gateway that allows a VPC to communicate with the internet when the necessary settings are configured.**

### Real-Life Example

Imagine your house has a gate that connects it to the outside world.

- House = VPC
- Gate = Internet Gateway
- Outside world = Internet

The gate provides a way out, but it does not mean every person inside the house can automatically go outside.

In the same way, attaching an IGW to a VPC does not automatically give every resource internet access.

### Example

```text
                 INTERNET
                     |
                     |
             Internet Gateway
                     |
                     |
                    VPC
                     |
                   Subnet
                     |
                  EC2 Instance
```

This is a simplified concept diagram. Actual internet connectivity depends on routing and other required configurations.

### Remember

- An IGW is attached to a VPC.
- A Route Table can direct traffic towards an IGW.
- An IGW alone does not automatically make every resource internet-accessible.

---

### 2. What Is a Route Table?

A Route Table is a collection of rules that tells network traffic where to go.

### 🧠 Simple Definition

> **Route Table = A set of directions that tells network traffic where to go.**

### Real-Life Example

Imagine you are travelling to a destination.

A map gives you different directions depending on where you want to go.

A Route Table works similarly. It checks the destination IP address and selects a matching route.

### Example

A Route Table might contain these two routes:

```text
Destination       Target
--------------------------------
10.0.0.0/16       local
0.0.0.0/0         Internet Gateway
```

Let's understand them one by one.

### Route 1: Local Route

```text
10.0.0.0/16 → local
```

This route allows communication within the VPC's IPv4 network.

For example:

```text
EC2 Instance A
10.0.1.10
       |
       | VPC internal traffic
       |
EC2 Instance B
10.0.2.20
```

Both IP addresses belong to the VPC range `10.0.0.0/16`.

The local route handles traffic between these addresses when the route applies.

### Route 2: Default Route

```text
0.0.0.0/0 → Internet Gateway
```

This route provides a default path for IPv4 traffic when a more specific matching route is not available.

We will understand this route in the next section.

### Remember

- A Route Table contains routing rules.
- The destination IP helps determine which route is selected.
- A route tells traffic where to go; it does not guarantee that the destination is reachable.

---

### 3. What Does `0.0.0.0/0` Mean?

This is one of the most important concepts from Day 24.

### Simple Definition

> **`0.0.0.0/0` = A route destination that matches every IPv4 address.**

It is commonly used as a default route.

### Example

```text
0.0.0.0/0 → Internet Gateway
```

This means:

If no more specific matching route is available, use the Internet Gateway as the next target for the IPv4 traffic.

### What Is a Default Route?

A default route is used when no more specific matching route is available for the destination.

Imagine that you have these routes:

```text
10.0.0.0/16 → local
0.0.0.0/0   → Internet Gateway
```

Now consider two destinations.

**Example A:**

```text
Destination IP: 10.0.2.25
```

This address belongs to `10.0.0.0/16`.

The local route is more specific, so the local route is selected.

**Example B:**

```text
Destination IP: 8.8.8.8
```

This address does not belong to `10.0.0.0/16`.

Assuming no other matching route exists, the default route sends the traffic towards the Internet Gateway.

### 🧠 Easy Memory Trick

```text
Destination inside VPC range
        ↓
Use the matching local route

Destination outside VPC range
        ↓
Use the default route if no
more specific route matches
```

**Important:** `0.0.0.0/0` does not mean that every packet must go through the IGW. A more specific matching route can take priority.

## 4. How Does a Route Table Connect a Subnet to the Internet?

Let's put the concepts together.

For a subnet to be a public subnet, its associated Route Table must have a route to an Internet Gateway.

### Example Architecture

```text
                  INTERNET
                      |
                      |
               Internet Gateway
                      |
                      |
              ┌───────────────┐
              │   Route Table │
              │               │
              │ 10.0.0.0/16   │ → local
              │ 0.0.0.0/0     │ → IGW
              └───────────────┘
                      |
                      |
                Public Subnet
                      |
                      |
                  EC2 Instance
```

### Routing Flow

Suppose an EC2 instance sends traffic to `8.8.8.8`.

1. The instance sends a packet towards its destination.
2. The subnet's associated Route Table checks the destination IP.
3. The local route does not match the external destination.
4. The default route `0.0.0.0/0` matches.
5. The packet is directed towards the Internet Gateway.

For the EC2 instance to communicate with the public internet, additional requirements must also be satisfied.

These include appropriate public IP addressing, security rules, and the required network configuration.

### Remember

**Route Table → Internet Gateway → Internet**

This is the basic routing path you should understand.

## 5. What Makes a Subnet Public?

### Simple Definition

> **A public subnet is a subnet whose associated Route Table has a route to an Internet Gateway.**

A common configuration is:

```text
Destination       Target
--------------------------------
10.0.0.0/16       local
0.0.0.0/0         igw-12345
```

Here, `igw-12345` is an example Internet Gateway ID.

The important part is:

```text
0.0.0.0/0 → Internet Gateway
```

The route table must be associated with the subnet.

### Public Subnet vs Internet-Accessible EC2

These are two different things.

**Public subnet:**
- Its associated Route Table has an IGW route.

**EC2 with internet connectivity:**
- The subnet's routing must support the traffic.
- The EC2 instance needs suitable public IP addressing for direct public IPv4 internet communication.
- Security rules and other necessary configurations must allow the traffic.

### Important Rule

```text
Public subnet
      ≠
Every resource is automatically
accessible from the internet
```

A public subnet does not automatically make all its resources publicly accessible.

## 6. What Happens When the IGW Route Is Deleted?

Suppose the Route Table initially contains:

```text
10.0.0.0/16 → local
0.0.0.0/0   → IGW
```

An administrator deletes the default route.

The Route Table now contains:

```text
10.0.0.0/16 → local
```

### What Changes?

**VPC internal communication:**

The local route still exists, so traffic covered by that route can continue to use it.

**Internet-bound traffic:**

The Route Table no longer has that default IGW route. If no other matching route provides a path, traffic cannot use the deleted route to reach the internet.

### Remember

Deleting the IGW route does not automatically delete the local route.

```text
Local route remains
        ↓
VPC internal routing can continue

IGW default route removed
        ↓
No default IGW path in that Route Table
```

## 7. Common Mistakes to Avoid

### Mistake 1: Thinking that attaching an IGW is enough

**Incorrect:** Attach an IGW and every EC2 instance gets internet access.

**Correct:** Routing and other required network settings must also be configured.

### Mistake 2: Thinking `0.0.0.0/0` is only for internet traffic

`0.0.0.0/0` matches all IPv4 destinations. It acts as the default route when no more specific matching route is available.

The route's target determines where the traffic is directed.

### Mistake 3: Thinking every matching route has equal priority

When multiple routes match a destination, AWS selects the most specific matching route.

For example:

```text
10.0.0.0/16 → local
0.0.0.0/0   → IGW
```

For destination `10.0.2.25`, the local route is more specific and is selected.

### Mistake 4: Thinking a public subnet makes every resource public

A public subnet's routing configuration does not automatically provide public internet connectivity to every resource inside it.
